# 측정 루프 — 변경과 성과를 분리한다

최적화 작업은 두 종류의 결과를 구분한다.

1. **기술 결과**: robots, sitemap, status code, 렌더링, structured data 등이 의도대로 바뀌었는가
2. **성과 결과**: 노출, 클릭, 순위, 전환, AI 출처 노출이 실제로 달라졌는가

기술 변경 완료를 성과 개선으로 표현하지 않는다.

## 1. 변경 전 기준선

가능하면 변경 전에 저장:
- Google Search Console: 클릭, 노출, CTR, 평균 게재순위
- 색인/페이지 상태
- Naver Search Advisor 지표
- 고정 AI 질문 세트의 출처 노출
- 전환/회원가입/문의 등 사업 KPI
- 서버 로그의 주요 크롤러 요청(가능한 경우)

기간과 데이터 최신일을 반드시 적는다.

## 2. 측정 시점

- **즉시**: HTTP, robots, sitemap, canonical, structured data, 렌더링 검증
- **약 14일**: 초기 방향성 체크포인트
- **약 28일**: 검색 성과 비교의 기본 창
- **분기**: 브랜드/엔티티 및 장기 AI 검색 가시성

[OFFICIAL] 검색 반영 속도는 사이트와 변경 종류에 따라 달라진다.
따라서 14일은 보장 기간이 아니라 운영 체크포인트다.

## 3. 비교 원칙

- 동일 요일/계절성 가능하면 통제
- 최근 데이터 지연 구간 표시
- 브랜드/비브랜드 검색어 분리
- 신규/기존 페이지 분리
- 변경이 여러 개면 동시 실험의 한계 기록
- 소표본은 큰 퍼센트 변화보다 절대값과 신뢰도를 함께 본다

## 4. AI 출처 측정

질문 세트를 버전 관리한다.

```csv
date,engine,question,domain_present,cited_url,answer_correct,notes
2026-08-27,ChatGPT,"...",yes,https://example.com/a,yes,""
```

주의:
- 같은 질문도 시간·위치·모델·로그인 상태에 따라 달라질 수 있다.
- 1회 출처 노출은 "랭킹 확보"가 아니다.
- 질문 세트를 중간에 바꾸면 전후 비교가 깨진다.

## 5. 데이터 신선도

각 지표에는:
- 측정 기간
- 마지막 데이터 날짜
- 수집일
을 함께 저장한다.

"0이 아님"보다 "얼마나 최신인가"를 먼저 확인한다.
